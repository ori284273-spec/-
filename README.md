# 闪彩 Atelier

本地优先的闪彩风格拆解与插画提示词工作台。Python HTTP 服务 + SQLite + 原生浏览器界面，没有线上图像生成或视觉模型依赖。

## 启动

需要 Python 3.12+、Pillow（当前环境已安装）。

```sh
cd /workspace/-
python -m pip install --disable-pip-version-check -r requirements.txt
python server.py --port 3000
```

服务监听 3000 端口。资料在 `.data/studio.db`，图片在 `.data/images/`；不会写入 Git。未来会话需要重新启动进程。不要将该无认证的个人工作台暴露到公共网络。

## 第一阶段工作流

1. 在参考资料库导入风格图片和人物 ZIP（单个上传最大 512 MiB，ZIP 解压总量上限 1 GiB）。支持 PNG/JPEG/WebP/GIF/BMP；归档内 TXT/MD/JSON/CSV 仅作为文本资料。
2. 对同一张图片分别建立风格卡、构图卡。编辑中文观察、英文词、适用范围、置信类型、人工确认与排除项；可逐项启用、拆分和合并。修改保存为新版本。
3. 在人物身份库逐张查看素材，标注正面/左右 3/4/侧脸与五官清晰度。筛选按人工面部标记和图片分辨率排序，不冒充人脸识别。建立英文稳定身份特征，临时服装、光照和表情独立记录。
4. 工作台分别选择风格卡、构图卡。输入剧情后使用规则候选（非 AI 对话），确认一个可见事件，或手动改写事件、动作、场景和服装。其他分类的卡片可在细节面板选取。
5. 编译时检查身份缺失、未知信息、全身/近景冲突等。补充或确认英文叙事。编译结果包含英文提示词及逐项来源，不发送任何图片，`generation_images` 为 `[]`。
6. 复制提示词到 ChatGPT Images。若需更强人物一致性，主动在 ChatGPT 中附加人物参考图，说明只继承人物结构。
7. 在创作记录导入结果，与当次身份参考并排检查，保存七项人工评价和校准备注。

参考卡是关键词索引，不是生成服务输入。没有接入模型时，不提供虚假的自动识图、自动翻译或生图按钮。文字约束不能保证人物脸部完全一致。

## 附件状态

预置 2 张人工观察卡来自用户消息中第一张风格图，均标为视觉估计。页面中的色块是占位示意，不是原图。导入原文件后可通过编辑卡片关联原图。

用户的人物 ZIP 超过聊天下载工具 32 MiB 限制，开发期间无法读取，未虚构角色、人物图或面部特征。可从网站直接导入该 ZIP，再完成素材筛选。应用尚无该角色的实际生成结果，一致性未获验证。

## 数据结构

- `images`: 内容哈希 ID、本机 URL、源文件名、原始尺寸、用途、视角、面部清晰人工标记。
- `cards`: 八个分类之一、原图关联、来源、排除项、版本、修改历史。
- `keywords`: ID、中文描述、英文词、适用范围、启用状态、证据类型、人工确认、冲突 ID。
- `identity`: 固定特征、多视角引用、表情视角变化、临时造型；默认锁定。
- `records`: 编译文本、当次人物母版快照、卡片版本和逐项来源、无图片生成载荷、结果图、人工评价。

SQLite 使用版本比较避免多窗口静默覆盖。ZIP 不按源文件路径解压，图片重新编码成 JPEG 并按内容哈希去重；文本只作为资料，不执行文档指令。JSON 导出不含图片二进制，完整备份需要同时保存 `.data/`。

## 验证

```sh
python -m unittest discover -s tests -v
node --check static/app.js
# 环境需安装 Playwright，使用系统 /usr/bin/chromium
node tests/e2e.cjs
```

浏览器验收在临时目录启动独立服务，使用合成色块图片验证导入、身份、卡片拆分合并、冲突拦截、编译、追溯、刷新持久化、结果评价和手机布局，不把测试资料注入用户工作空间。
